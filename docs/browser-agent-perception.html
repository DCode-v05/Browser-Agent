How browser agents see pages

Checked against OpenAI and Hermes docs and source code, 3 October 2026

The claim: DOM and screenshots are how browser agents work.

Answer: partly true. Both are real inputs, but neither OpenAI nor Hermes is built as "DOM + screenshots". OpenAI's click tool uses screenshots only. Hermes leads with the accessibility tree. Both now prefer letting the model write code.

What each one does

SystemWhat the model seesHow it acts
OpenAI computer toolScreenshots only, no DOMClicks at pixel positions, types, scrolls, presses keys
OpenAI code execution (recommended)Screenshots plus what the script printsModel writes a Playwright or PyAutoGUI script; one call does many steps
OpenAI hosted browser (Agents API)Not visible to us; only screenshots come backNot exposed
Codex / ChatGPT desktop browserScreenshots and rendered page; DOM only in an opt-in Developer modeModel writes JavaScript in a REPL
Hermes built-in toolsAccessibility tree as text, elements tagged @e1, @e2; screenshots as a fallbackClicks and types by element ID
Hermes default modeWhatever its code pulls: JavaScript, accessibility tree, screenshotsModel writes Python with Browser Use helpers

Codex CLI has no browser. The browser lives in the ChatGPT desktop app.

Where the proposal is off

  1. The DOM isn't the main input anywhere. A raw DOM is thousands of nested elements. Too big and noisy to feed the model every turn.
  2. It misses the accessibility tree. The browser builds it from the DOM: a short list of buttons, links and inputs with their labels, the same thing a screen reader reads. This is what Hermes relies on first.
  3. The bigger shift is code mode. The model writes a script that does several steps in one call, instead of one click per turn. Fewer round trips, and the script can use any of the inputs.

What we should build

  • Main input: accessibility tree with element IDs. Cheap and precise.
  • Screenshots: to check results, and for what text can't capture (charts, canvas, layout bugs).
  • DOM and JavaScript: for pulling data and debugging, not as the main input.
  • Actions: a code tool (Playwright or Chrome DevTools Protocol) for multi-step work, plus simple click and type tools by element ID.

OpenAI's hosted browser and ChatGPT's browser are closed source, so for those this reflects their docs and public code only.
